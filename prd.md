# PRD: Бот для трекинга подписок

**Название бота:** SubTrack  
**Username в Telegram:** [@ris_subtrack_bot](https://t.me/ris_subtrack_bot)

**Суть проекта (1–2 предложения):**  
Персональный Telegram-бот, в котором пользователь ведёт список регулярных подписок (стриминг, SaaS, VPN, облако и т.п.) и видит, сколько денег уходит в месяц и когда ближайшие списания. Все суммы — **только в долларах (USD)**. Бот напоминает о платежах заранее и позволяет отметить «оплачено», сдвинув дату на следующий период.

**Цель бота / проблема, которую он решает:**  
Подписки размазаны по разным сервисам и картам — легко забыть списание, не понимать суммарную нагрузку на бюджет и пропускать отмену ненужного. Бот даёт один список, прозрачную «месячную» стоимость и своевременные напоминания без отдельного приложения и таблиц.

**Аудитория:**  
Взрослый пользователь Telegram (25–45), который сам платит за цифровые сервисы: развлечения, облако, VPN, AI-инструменты, подписки на софт. Ситуация: «хочу раз в неделю глянуть, сколько трачу, и не проспать списание». Устройство — в первую очередь **смартфон** (мобильный Telegram): короткие сессии, кнопки внизу экрана, минимум ввода с клавиатуры, inline-кнопки там, где можно выбрать из вариантов.

**MVP = только этот Mac (граница версии):**  
Первая версия считается готовой, когда бот **стабильно работает локально на твоём компьютере** — не на VPS, не в Docker в облаке, не «для всех пользователей интернета». Один владелец, один Mac, один процесс в терминале, одна база в папке проекта.

**Развёртывание:**  
Запуск: `python main.py` в каталоге проекта на Mac. Данные: `data/subscriptions.db` на диске **этого же** компьютера. Пока Mac выключен или процесс не запущен — бот не отвечает в Telegram и **не шлёт напоминания**. Команды `/list`, `/stats` и добавление подписок доступны только когда бот запущен; между перезапусками данные сохраняются на диске.

**Вне scope MVP:** деплой на сервер, always-on 24/7, доступ с другого ПК без копирования проекта, мультипользовательский хостинг. Это возможные улучшения после MVP, но **не входят в критерий «v1 готов»**.

**Технологический стек (v1):**


| Слой         | Выбор                                | Зачем                                                                                                         |
| ------------ | ------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| Язык         | **Python 3.11–3.13** (на Mac — 3.13) | Простой локальный запуск, много примеров для AI-агента; **не** Python 3.14 (зависимости бота могут не встать) |
| Telegram API | **aiogram 3**                        | Асинхронный бот, FSM для диалога `/add`, inline-кнопки, long polling                                          |
| База данных  | **SQLite** через **aiosqlite**       | Один файл `data/subscriptions.db` на диске Mac, бэкап = копия папки                                           |
| Конфиг       | **python-dotenv**                    | Токен бота в `.env` (`BOT_TOKEN`, опционально `REMIND_DAYS_BEFORE=3`)                                         |
| Напоминания  | **asyncio**-цикл в фоне              | Раз в ~1 час проверка БД и отправка напоминаний; отдельный cron/JobQueue не нужен для личного MVP             |


**Структура проекта:**

```
main.py                 # точка входа: python main.py
bot/
  handlers.py           # команды, диалоги, callback-кнопки
  database.py           # SQLite: подписки, напоминания
  reminders.py          # фоновая проверка дат списания
  states.py             # шаги FSM при добавлении
  keyboards.py          # reply- и inline-клавиатуры
  formatters.py         # тексты карточек и списков
data/
  subscriptions.db      # создаётся автоматически
.env                    # BOT_TOKEN (не коммитить)
requirements.txt
```

**Зависимости (`requirements.txt`):**

```
aiogram==3.20.0
aiosqlite==0.21.0
python-dotenv==1.1.0
```

**Почему этот стек для MVP:** заточен под «запустил на Mac → работает»; FSM для `/add`; AI-агент хорошо генерит такой код; без Node, без облака, без отдельного cron на сервере.

**Не в MVP (отложено):** Node.js + grammY, python-telegram-bot + JobQueue, pyTelegramBotAPI, VPS/Railway/Render, PostgreSQL, веб-админка, always-on без твоего Mac.

**Стиль общения бота:**  
Русский язык, обращение на **«ты»**. Тон — дружелюбный и деловой, без канцелярита и без «сюсюканья»: короткие сообщения, эмодзи как ориентиры (✅ 📋 🔔), не больше 3–4 строк за раз. Примеры формулировок: «Подписок пока нет», «Сегодня списание», «≈ $42/мес». Суммы всегда с символом `$`. Без финансовых советов и без морализаторства про траты.

**MVP — что должно работать в первой версии (локально на этом Mac):**

0. **Среда:** бот запускается и проходит все сценарии ниже **только** на Mac владельца, из папки проекта, с локальным `subscriptions.db`. Облачный деплой не требуется и не проверяется.
1. Регистрация контекста по `user_id` Telegram — данные одного пользователя не видны другому (для личного бота это защита «на всякий случай», не мультиаккаунтный продукт).
2. Добавление подписки: название → сумма в **USD** (шаг выбора валюты отсутствует) → период. **Дату не спрашиваем:** следующее списание = сегодня + один выбранный период. В карточке — сумма в `$` и рассчитанная дата.
3. Команда `/date` — выбор подписки и ввод другой даты, если дефолт не подошёл.
4. Просмотр списка с индикацией срочности (🟢 > 7 дн., 🟡 4–7 дн., 🔴 ≤ 3 дн.).
5. Статистика: приведение всех подписок к **$/мес** (неделя × 52/12, год ÷ 12) — одна итоговая сумма в долларах.
6. Удаление подписки из списка.
7. Автонапоминания за `REMIND_DAYS_BEFORE` дней (по умолчанию 3), накануне и в день списания — с кнопкой «Оплачено».
8. Сдвиг даты следующего платежа после «Оплачено» по выбранному периоду.
9. Хранение в SQLite **на Mac** (`data/subscriptions.db`), запуск одной командой `python main.py` в терминале на локальной машине.

**Критерий готовности MVP (локальный Mac):**

- На **этом Mac** в терминале: `python main.py` — процесс стартует без ошибок, бот онлайн в Telegram.
- Бот отвечает на `/start` в течение 2 секунд и показывает reply-меню из 4 кнопок.
- Полный цикл `/add` (3 шага + период, без даты и без выбора валюты) → подписка в `/list` с суммой в `$`, периодом и автодатой «сегодня + период».
- `/date` меняет `next_payment` на введённую дату; в `/list` отображается новое значение.
- `/stats` для двух подписок (месяц + год) показывает осмысленную сумму «в месяц» (годовая ÷ 12).
- Подписка с датой «сегодня + 2 дня» получает напоминание; повторно за ту же дату не дублируется.
- Кнопка «Оплачено» сдвигает `next_payment` вперёд (месяц +1 для monthly).
- `/delete` удаляет запись; в `/list` её больше нет.
- Второй Telegram-аккаунт не видит подписки первого.
- После перезапуска процесса на Mac данные сохраняются в `data/subscriptions.db`.
- При остановленном процессе бот не отвечает; после повторного `python main.py` на **том же Mac** — снова работает с теми же данными.
- **MVP закрыт без деплоя:** не требуется настройка VPS, systemd на сервере, webhook в облаке.

**Ограничения:** (чего бот точно НЕ должен делать)

- **MVP = только локальный Mac** — не продукт «в облаке». Нет VPS/Railway/Render в v1, нет SLA uptime, нет работы с другого компьютера без переноса папки и БД. Напоминания — пока Mac включён и `python main.py` запущен.
- Не подключается к банкам, Apple/Google Pay и не парсит выписки.
- Не списывает деньги, не отменяет подписки в сервисах за пользователя.
- Не ведёт семейный/shared доступ и не синхронизируется с Notion/Excel.
- Не даёт инвестиционных, налоговых и юридических рекомендаций.
- Не требует регистрации кроме Telegram; нет веб-кабинета и email-рассылок; не рассчитан на публичный хостинг и многих пользователей одновременно.
- **Только USD** — нет рублей, евро и переключения валют; пользователь вводит сумму как доллары.
- Не поддерживает в MVP: редактирование суммы/названия/периода (только дата через `/date`), категории, произвольные напоминания, экспорт, общий доступ, админ-панель.
- Не гарантирует точность «месячной» суммы для подписок с плавающим днём списания — только приближённый расчёт для обзора.
